# 讲解与符号规范

本站把符号解释视为正文的一部分。读者可以直接进入任意章节、切换任意阅读深度，不应依靠记住前面章节的记号才能继续。

## 每个小节的顺序

1. 标题说明正在解决的具体问题。
2. `notation` 列出本节需要的字母、下标、操作符、缩写及其含义；涉及张量时给出形状。符号表直接显示，不藏在悬停提示里。
3. 正文先说目的，再讲一个可追踪的例子。短段落一次解释一个关键动作。
4. `formulaReading` 用中文读出公式的运算顺序，之后再显示公式。
5. 适合时用 `flow` 展示计算顺序，用 `checkpoint` 给一个可展开答案的小问题。答案不是评分，不计入学习进度。

## 符号必须根据上下文定义

- 不只定义字母，也定义求和、连乘、偏导、梯度、转置、条件概率竖线、期望、范数、取整、指示函数等操作符。
- 区分“下标是编号”和“上标是乘方”；区分同一符号在不同章节里的意义。
- 例如卷积中的大写 `W` 可能表示权重，也可能出现在形状中表示宽度；两种用法必须分别说明。
- 每一段 `formula` 都必须有本节的 `notation` 和 `formulaReading`。不要自动套一个不符合本节变量含义的全站字典。
- `notation.symbol` 用合法 LaTeX。TypeScript 中优先使用 `String.raw`，防止反斜杠被误读为制表符、换行符等。
- 正文和实验控件中的新缩写也应就近解释。学习内容中不要出现面向开发者的调试说明。

## 内容与代码

- 每章保留速通、深入、实现三个层次。相关目录主题可以共享一章，但必须有对应内容，不能只因为提到一个名字就标为完成。
- 代码块应可独立复制运行，使用小规模 CPU 例子；不要依赖其他代码块的变量、私人数据、API 密钥或在线下载权重。
- 说明示例的输入输出、维度、目标和应观察到的结果。教学数值不冒充真实模型性能。
- 保留原始论文、课程或官方文档的链接和阅读理由。新增模型应说明适用问题、关键机制、限制及易混淆之处。

## 发布前验证

内容检查验证全部目录主题有对应章节，公式附有定义与中文读法；KaTeX 检查全部公式与符号是否能渲染。Python 示例逐段独立执行。浏览器检查覆盖全部章节的三个阅读深度、旧链接、专注阅读、核心实验和手机/平板宽度。

这些自动检查不能证明讲解在语义上完整或对所有读者都足够清楚，仍需要逐章审校、交叉检查数字例子，并根据实际阅读反馈修订。
